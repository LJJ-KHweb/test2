# 개발용 데이터베이스 구성 

현재 저장소의 MyBatis 매퍼와 요청 DTO를 기준으로 작성한 **Oracle 21c XE용 신규 DB 구성안**입니다. 기존 운영 DB의 원본 DDL을 추출한 파일이나 기존 DB를 변경하는 마이그레이션 스크립트가 아닙니다. 다른 DBMS로 전환하는 경우 매퍼 SQL과 JDBC 설정도 별도로 변경해야 합니다.

## 파일 구성

| 파일 | 용도 |
| --- | --- |
| [schema.sql](schema.sql) | 테이블 9개, 기본값, PK·FK·UNIQUE·CHECK 제약조건, 인덱스 생성 |
| [seed.sql](seed.sql) | API로 가입한 테스트 회원에 레시피·알레르기·즐겨찾기·걸음 수 예시 연결 |
| [verify.sql](verify.sql) | 생성된 데이터 수와 필터링·추천 결과를 조회하는 확인용 SQL |

스크립트는 UTF-8로 저장되어 있습니다. SQL Developer 또는 SQLcl에서 UTF-8로 열고 스크립트 실행 기능을 사용합니다. SQL*Plus를 사용하는 경우 클라이언트 인코딩도 UTF-8에 맞춥니다. `SET DEFINE OFF`는 `국&찌개`의 `&`가 치환 변수로 처리되는 것을 방지합니다.

## 1. 빈 애플리케이션 스키마 준비

Oracle PDB(예: `XEPDB1`)에 생성된 개발용 계정을 사용합니다. 이 계정에는 `CREATE SESSION`, `CREATE TABLE`, `CREATE SEQUENCE` 권한과 테이블스페이스 할당량이 필요합니다. SYS/SYSTEM 계정으로 실행하지 않습니다.

계정 생성과 권한 설정은 DB 환경에 따라 다르므로 이 파일에서는 수행하지 않습니다. `DB_USERNAME`에 설정할 애플리케이션 계정으로 접속한 상태에서 다음 스크립트를 실행합니다.

```sql
@schema.sql
```

위 명령은 `db` 폴더를 현재 작업 디렉터리로 사용한 예시입니다. SQL Developer에서는 해당 파일을 열고 **스크립트 실행(F5)**을 사용해도 됩니다.

대상 테이블 이름이 이미 존재하면 생성 전에 중단합니다. DROP이나 기존 데이터 삭제는 포함하지 않습니다. Oracle DDL은 자동 커밋되므로 중간 오류가 나면 앞서 생성된 객체는 남습니다. 재실행 전에 오류 원인과 이미 생성된 객체를 확인해야 합니다.

### 테이블 관계

| 테이블 | 주요 역할 및 관계 |
| --- | --- |
| `MEMBER` | 회원 정보. 아이디는 전체 회원 기준 고유 값 |
| `TOKEN` | 회원별 Refresh Token의 JTI와 밀리초 단위 만료 시간 |
| `MEMBER_ALLERGY` | 회원별 알레르기 재료 |
| `RECIPES` | 작성 회원을 참조하는 레시피 및 영양 정보 |
| `MATERIAL` | 레시피별 재료 및 분량 |
| `RECIPE_STEPS` | 레시피별 조리 단계. 레시피 내 단계 순서는 고유 값 |
| `BOOKMARK` | 회원 번호와 레시피 번호를 복합 PK로 사용하는 즐겨찾기 |
| `DEVICE` | 회원당 1개의 디바이스 |
| `STEP_LOG` | 디바이스별 누적 걸음 수 보고 기록 |

암호화된 이메일·연락처는 평문보다 길어지므로 각각 512바이트로 정의했습니다. 이메일·연락처의 중복 여부는 기존 코드처럼 활성 회원의 HMAC 해시로 검사하며, DB UNIQUE 제약을 추가하지 않았습니다.

조리 단계 설명은 DTO의 최대 2,000자와 한글을 수용하도록 `NVARCHAR2(2000)`으로 정의했습니다. 레시피 순서 변경 중 `STEP_ORDER`에 임시로 1,000을 더하므로 단계 순서에는 작은 상한을 두지 않았습니다. 이미지 컬럼은 샘플 데이터에서 NULL을 허용하지만, API를 통한 레시피 등록은 기존 코드대로 대표 이미지가 필수입니다.

## 2. 애플리케이션 실행 및 테스트 회원 가입

상위 [README](../README.md)의 설정으로 백엔드를 실행합니다. SQL 파일은 Spring Boot 시작 시 자동 실행되지 않으며 수동으로 적용합니다.

Swagger UI의 `POST /api/auth/signup` 또는 API 클라이언트에서 아래 개발용 계정을 생성합니다. `memberPwd`는 예시 비밀번호이므로 실제 서비스 계정에 사용하지 않습니다.

```json
{
  "memberId": "demouser",
  "memberPwd": "DemoPass123!",
  "memberName": "테스트회원",
  "phone": "01000000000",
  "email": "demo@example.com"
}
```

회원가입 API가 비밀번호 BCrypt 해시, 이메일·연락처 AES 암호화, 중복 확인용 HMAC을 현재 설정 키로 생성합니다. SQL에 평문 회원 정보를 직접 넣지 않습니다. 같은 데이터를 계속 사용할 때는 AES·HMAC 키도 유지해야 합니다.

회원가입이 성공하면, 알레르기나 디바이스 등을 직접 등록하기 전에 다음 단계로 진행합니다.

## 3. 예시 데이터 적용

동일한 애플리케이션 DB 계정으로 새 SQL 세션을 열어 실행합니다.

```sql
@seed.sql
```

`seed.sql`은 활성 회원 `demouser`를 찾아 데이터를 연결합니다. 회원 번호·레시피 번호·디바이스 번호는 DB가 생성한 값을 사용하며 고정 ID를 가정하지 않습니다. 실행이 완료되면 커밋하고, 중간 오류가 발생하면 예시 데이터 삽입을 롤백합니다. 별도 세션에서 실행해 다른 미완료 작업과 섞이지 않도록 합니다.

회원이 없거나 해당 회원에게 레시피·알레르기·즐겨찾기·디바이스 데이터가 이미 있으면 삽입 전에 중단합니다. 성공 후 재실행해도 중복 데이터를 추가하지 않으며, 기존 데이터를 삭제하거나 덮어쓰지 않습니다.

| 데이터 | 생성 내용 |
| --- | --- |
| 회원 | SQL에서 추가하지 않음. API로 가입한 `demouser` 사용 |
| 알레르기 | 땅콩, 우유 |
| 레시피 | 총 6개. 650·700·750·690·710 kcal와 칼로리 미입력 레시피 |
| 재료·조리 단계 | 레시피별 재료 2개, 조리 단계 2개 |
| 즐겨찾기 | 닭고기 덮밥, 두부 채소밥 |
| 디바이스 | 회원에 연결된 디바이스 1개 |
| 걸음 수 | 이전 6일 각 1건과 오늘 2건, 총 8건 |

레시피의 재료·분량·칼로리·조리 단계는 기능 확인용 값입니다. 실제 이미지와 S3 객체는 제공하지 않으므로 이미지 컬럼은 NULL이며, 이미지 표시·업로드 확인에는 별도 이미지가 필요합니다. Refresh Token은 샘플로 삽입하지 않고 실제 로그인 시 생성합니다.

## 4. 데이터 확인

```sql
@verify.sql
```

이 파일은 데이터를 변경하지 않고 회원별 행 수, 필터 적용 결과, 한 끼 700 kcal 추천 결과, 일별 걸음 수를 조회합니다.

초기 데이터 적용 직후의 예상 결과는 다음과 같습니다.

| 확인 항목 | 예상 결과 |
| --- | --- |
| 전체 레시피 목록 | 6개 |
| `demouser`의 알레르기 필터 적용 목록 | 4개. 땅콩버터 비빔면과 우유 감자수프 제외 |
| 하루 목표 2,100 kcal 추천 | 두부 채소밥(700), 닭고기 덮밥(650), 버섯 볶음밥(750) 순서 |
| 칼로리 미입력 과일 컵 | 목록에는 포함, 칼로리 추천에서는 제외 |
| 즐겨찾기 | 2개 |
| 오늘 걸음 수 기록 | 1,000걸음과 3,600걸음의 누적 기록 2개 |
| 최근 7일 기록 | 7일치. 오늘의 총 걸음 수는 최댓값인 3,600 |

위 개수는 다른 데이터가 없는 신규 DB 기준이며, 추천 순서는 조회수 등 데이터를 변경하기 전 기준입니다. 걸음 수의 오늘/최근 7일 기준은 매퍼와 동일하게 Oracle의 `SYSDATE`를 사용합니다. 날짜가 바뀌면 조회 범위와 결과도 달라집니다.

API까지 확인하려면 `demouser`로 로그인하고 Access Token을 보내 레시피 목록, 칼로리 추천, 즐겨찾기, 일별·주간 걸음 수를 조회합니다.

## 검증 범위

DDL과 예시 데이터는 저장소 코드에 맞춰 작성했습니다. 실제 Oracle 서버에서 스키마 생성, 데이터 삽입, 애플리케이션 연동까지 실행 검증한 상태는 아닙니다. 기존 DB에서 옮겨오는 경우에는 실제 DDL과 데이터를 비교해 별도의 마이그레이션을 준비해야 합니다.
